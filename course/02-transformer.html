Foundations

How a transformer works

Tokens, the residual stream, attention, and MLPs — from scratch

To take a transformer apart, you need a clear picture of what it is. This lesson builds one from the ground up. We will keep it concrete by using the exact sizes of the model in this course wherever it helps.

Everything is a sequence of vectors

A transformer reads a sequence of tokens (here, symbols like the key k17 or the value v5) and, at every position, produces a prediction for what token comes next. Internally it never works with the symbols directly — it works with vectors.

Definition

Token — one atomic symbol from a fixed vocabulary. Embedding — a lookup table with one learned vector per vocabulary token. Turning a token into its vector is the model's first act. In our model each vector has 48 numbers (we say the model is "48-dimensional", d_model = 48).

Position matters ("first" versus "third" is different), but a lookup table only knows which token, not where it is. So the model also has a positional embedding: one learned vector per slot in the sequence, added to the token vector. The starting vector at each position is therefore token_vector + position_vector.

The residual stream: a shared workspace

Here is the single most important idea for interpretability. Those per-position vectors form the residual stream: a running 48-dimensional vector at each position that every part of the network reads from and writes to. Components do not pass messages to each other directly; they all add their output into this shared stream.

# the residual stream at one position, flowing down through the network
x = token_embedding + position_embedding   # the starting vector
x = x + attention_layer_0(x)                # each component ADDS its output
x = x + mlp_layer_0(x)
x = x + attention_layer_1(x)
x = x + mlp_layer_1(x)
logits = unembed(x)                         # read out a prediction
Why this matters for us

Because every component adds into the same stream, we can ask of any vector in it: which components put what here, and what does it encode? Most of our techniques — probing, logit attribution, patching — are ways of interrogating this stream. Keep this diagram in your head for the whole course.

Attention: moving information between positions

So far each position is processed on its own. Attention is the only operation that lets positions share information — it lets the vector at one position pull in information from the vectors at other positions.

It works in two halves. For each pair of positions (a query position doing the looking, and a key position being looked at):

  • Where to look (the QK circuit). The query produces a "query vector," each other position produces a "key vector," and their dot product is a score: how relevant is that position to this one? Softmax turns the scores across all positions into attention weights that sum to 1 — a spotlight that can be sharp (all on one position) or diffuse.
  • What to bring back (the OV circuit). Each position also produces a "value vector." The query position takes a weighted average of those value vectors, using the attention weights, and adds the result into its own residual stream.
Definition

An attention head is one independent copy of this where-to-look / what-to-bring-back machinery. A layer can have several heads running in parallel, each free to specialize. Our model has 2 heads per layer. "L1H0" means layer 1, head 0.

Two facts we will lean on constantly: attention weights are easy to visualize (they are just a grid of numbers per head — the "heatmaps" of the next lesson), and the QK and OV circuits are separable — a head decides where to look independently of what it copies.

The MLP: per-position computation

After attention has moved information around, each position is processed on its own again by a multi-layer perceptron (MLP): a small two-step function (expand to a wider hidden layer, apply a non-linearity, project back) that transforms the vector in place and adds the result to the stream. Attention mixes across positions; the MLP computes within a position. Ours has a hidden width of 96.

Depth, and reading out an answer

A layer (or "block") is one attention step followed by one MLP step. Stacking layers lets later computation build on earlier computation — all through the shared stream. Our model has just 2 layers, which is part of why we can understand it completely.

At the end, the final residual vector at a position is multiplied by an unembedding matrix to produce a logit (a score) for every vocabulary token; softmax turns those into probabilities, and the highest one is the model's prediction for the next token.

Definition

Autoregressive generation — the model predicts one token, appends it to the sequence, and predicts the next, and so on. A causal mask enforces the rule that a position may only attend to earlier positions, never later ones — you cannot peek at the future you are trying to predict. Whether a model is causal turns out to be decisive for our task, as we will see.

One small but important detail: before attention and before the unembedding, the stream passes through LayerNorm, which rescales each vector to a standard size. It mostly does not change which direction a vector points, so for interpretation we can often treat it as a fixed scaling and look through it — a trick we will use when we attribute logits to components.

You now know enough

Tokens become vectors; the residual stream is a shared per-position workspace; attention moves information between positions in a visible, separable way; MLPs compute within a position; and the final vector is read out into a next-token prediction. That is the whole machine. Next we meet the specific one we will dissect.
